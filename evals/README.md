# Джйотиш-сервис · Eval System

Трёхслойная система верификации, предотвращающая ошибки типа «Луна в Близнецах вместо Стрельца».

---

## Почему это важно

Первая версия альманаха для Анны (21.12.1976) содержала критические ошибки:

| Параметр | Было (ошибка) | Стало (верно) |
|---|---|---|
| Луна | Близнецы / Ардра | **Стрелец / Мула** |
| Текущая МД | Меркурий (2012–2029) | **Раху (2022–2040)** |
| Марс | Дева | **Скорпион (свой знак!)** |
| АК | Меркурий | **Юпитер** |

Причина: расчёт сделан без pyswisseph, тропическая позиция Луны принята за сидерическую.
Ошибка выявлена через vedic-horo.ru после публикации альманаха.

**Правило: расчёт → верификация → нарратив. Никогда не наоборот.**

## Три слоя верификации

### Слой 1 — Расчётный (вес 50%, порог 90%)
Единственный надёжный источник — pyswisseph с аянамшей Лахири.

**Проверяет:** знак, дом, ретроградность каждой планеты; накшатру Луны; текущую МД.

**Критично:** ошибка в знаке одной планеты = провал всего тест-кейса.

### Слой 2 — Логический (вес 30%, порог 80%)
Внутренняя согласованность карты: АК, ДК, йоги, бинду.

**Проверяет:**
- АК = планета с максимальным градусом в знаке (не абсолютным!)
- Суммарные бинду SAV в диапазоне 315–360
- ВБ Марса ≥ 12.5 при позиции в своём знаке

### Слой 3 — Нарративный (вес 20%, порог 85%)
Текст альманаха не противоречит расчётным данным.

**Проверяет:** наличие required_facts и отсутствие forbidden_facts в HTML-выводе.

## Использование

### Установка
```bash
pip install pyswisseph --break-system-packages
```

### Рассчитать карту
```bash
python verify_chart.py calculate \
  --date 1976-12-21 --time 10:32 \
  --lat 47.233 --lon 39.717 --tz 3 \
  --output anna_chart.json
```

### Верифицировать против evals.json
```bash
python verify_chart.py verify \
  --evals evals.json --eval-id 1 \
  --date 1976-12-21 --time 10:32 \
  --lat 47.233 --lon 39.717 --tz 3
```
Если pass rate < 90% — скрипт завершается с exit code 2 и блокирует генерацию нарратива.

### Запустить все evals (Анна как эталонный кейс)
```bash
python verify_chart.py run-all --evals evals.json
```

## Интеграция в сервис

**Обязательная последовательность для каждого нового альманаха:**

```
1. Получить данные рождения от пользователя
2. verify_chart.py calculate → chart.json       ← pyswisseph
3. verify_chart.py verify --evals evals.json    ← проверка
4. Если pass rate < 90% → СТОП, найти ошибку
5. Только если PASS → генерировать HTML-альманах
6. После генерации → Layer 3 нарративная проверка
```

**В промпте к LLM для генерации нарратива:**
```
Ниже — верифицированные данные карты из pyswisseph.
Используй ТОЛЬКО эти данные. Не додумывай позиции планет.
Если данные отсутствуют для какого-то параметра — укажи "не рассчитано".

[chart.json]
```

## Добавление нового эталонного кейса

1. Рассчитай карту через `verify_chart.py calculate --output new_user.json`
2. Сверь с vedic-horo.ru или astro.com
3. Добавь в `evals.json` новый объект с `ground_truth`
4. Присвой уникальный `id` и осмысленный `name`

## Известные источники ошибок

| Ошибка | Причина | Защита |
|---|---|---|
| Луна в тропическом знаке | Забыли вычесть аянамшу | Всегда `FLG_SIDEREAL` в swe.calc_ut |
| АК = не та планета | Сравнили абсолютные градусы, не градусы в знаке | `planet_lon % 30` для каждой грахи |
| Неверная МД | Неверная накшатра Луны (из-за тропика) | Проверять Слоем 1 перед любой МД-логикой |
| ВБ Марса низкий | Рассчитан для неверной позиции (Дева вместо Скорпиона) | Слой 2 проверяет ВБ ≥ 12.5 для Марса в своём знаке |
